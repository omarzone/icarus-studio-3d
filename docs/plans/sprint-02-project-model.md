# Sprint 2 · Project Model and Physics Design Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The engine owns real projects: create one from a template, change it only through validated edit operations, compile every candidate revision to MuJoCo, test it physically, keep an undoable revision history, and serve all of it over HTTP.

**Architecture:** Contracts first (`icarus/contracts/`), then the `design` zone: `library/` declares every component kind with its `PropertySchema`s, reward terms and templates (templates are lists of edit operations, so even a new project goes through the one edit model); `projects/` applies operation batches to a candidate document, validates structure and ranges, hands it to `design/` (MJCF compiler and design tests), and only a passing candidate becomes a revision in an append-only log; `design/` also exports a `SceneDescription` from the compiled model. Finally thin `api/` routers expose projects, operations, revisions, undo/redo, scene and library.

**Tech Stack:** Python 3.12 (uv), FastAPI, Pydantic v2, MuJoCo (new), pytest, ruff, pyright; `pnpm gen:contracts` to TypeScript.

**Spec:** [`roadmap.md`](./roadmap.md) › Sprint 2; [`docs/architecture.md`](../architecture.md) › Core idea, The contract, Library, Projects and edit operations, Objects components and property types, Design compilation and tests, HTTP API; [`services/engine/AGENTS.md`](../../services/engine/AGENTS.md); the desktop view types in `apps/desktop/src/renderer/ports/scene-port.ts` (what Sprint 3 must be able to map the contract onto).

## Global Constraints

- Zones: Task 1 is `contracts` and lands alone; Tasks 2–8 are `design`; Task 9 is `engine-api`; Task 10 is docs. Commits: `feat(contracts): …`, `feat(design): …`, `feat(engine-api): …`, `docs: …`.
- Pydantic v2, `ConfigDict(extra="forbid")` on every boundary model, explicit ranges with `Field(ge=…, le=…)`. Pyright `standard` clean. Ruff clean.
- SI units (m, kg, rad, s); quaternions **wxyz**; Z-up.
- Atomic writes for documents and pointers (`.tmp` then `os.replace`); revision log is append-only JSONL.
- Project ids are generated by the engine (`uuid4().hex[:12]`); no path is ever built from request text. Every resolved project path must stay inside the projects directory.
- No file named `utils`, `helpers`, `common`, `misc`, `manager`. Files ≤ ~400 code lines, tests ≤ ~800.
- New dependency: `mujoco` only (`uv add mujoco`, version published ≥ 3 days ago). Justify in the PR: it is the physical truth of the product; nothing else can compile MJCF.
- The API process may import `mujoco` (design tests are fast); it never imports the training stack.
- Tests offline and deterministic; nothing marked `slow` is needed this sprint.

## Review Focus

1. **Out-of-range or wrong-type property values** (mass −1, friction "abc", a vector of 2 numbers, a choice not in its options): rejected with HTTP 422 and a path like `objects.car.components.physics.mass`, never stored. Pinned in Task 2 and Task 9.
2. **Dangling references** (a motor whose joint was deleted, a joint whose parent object was removed, a reward term not in the library): structural validation error naming both ends, never a compile crash. Pinned in Task 4.
3. **Physically broken candidates** (zero-size geom, a 1 000 kg part on a 0.01 kg hinge chain, overlapping colliders that explode, MuJoCo raising): a failing `DesignReport` with readable reasons and no new revision; the engine never crashes or stores NaN. Pinned in Task 6.
4. **History edges:** undo at the first revision, redo with nothing to redo, a new edit after undo (the redo branch is dropped, old revisions stay in the log). Pinned in Task 7.
5. **Interrupted writes:** a crash between writing the snapshot and moving the head leaves the project readable at its previous revision. Pinned in Task 7 (simulated failure before `os.replace`).

### Task 2: Component library with property validation

**Files:**
- Create: `icarus/library/__init__.py`, `library/properties.py` (schema builders + `check_value`), `library/components.py` (the catalog), `library/catalog.py` (`library_catalog()`)
- Test: `tests/library/test_components.py`, `tests/library/test_properties.py`

**Interfaces:**
- Consumes: Task 1 models.
- Produces: `COMPONENTS: dict[str, ComponentKindSpec]`; `component_kind(kind: str) -> ComponentKindSpec` (raises `UnknownKind`); `check_value(schema: PropertySchema, value: PropertyValue) -> str | None` (problem text or `None`); `default_component(kind: str, id: str) -> ComponentSpec`; `LIBRARY_VERSION = "1"`.

Components v1 and their properties (SI, ranges inclusive):
- `transform` (Shape, unique): position vector m, rotation vector deg (applied XYZ), scale vector (0.01..100).
- `mesh` (Shape, unique): shape list box/sphere/capsule/cylinder/plane; size vector m (0.001..100).
- `material` (Shape, unique): color, surface list (asphalt, grass, ice, rubber, wood, metal) mapping to friction presets.
- `light` (World): kind choice sun/point, intensity slider 0..5, color.
- `physics_body` (Physics, unique): mode choice static/dynamic, mass number kg (0.001..10 000), density expert number (1..20 000).
- `collider` (Physics, unique): friction slider 0..2 (randomizable), restitution slider 0..1 (expert).
- `joint` (Physics, unique): kind choice hinge/slide/ball/fixed, axis vector, limits range (−180..180 deg or −10..10 m), damping expert number (0..100), connects_to asset (object id; empty = parent).
- `motor` (Physics, unique): joint asset (object id with a joint), kind choice position/torque, max_force number N (0..10 000), gear expert number (0.01..1 000).
- `distance_ray` (Senses): range number m (0.05..50), count count (1..32).
- `balance` (Senses, unique): includes choice accel+gyro / gyro.
- `touch` (Senses, unique): radius number m (0.005..1).
- `spawn_point` (World, unique), `goal_zone` (World, unique, radius number m 0.1..20), `zone` (World, size vector, effect choice slow/slippery/none).
- `surface` (World, unique): friction slider 0..2 (randomizable), kind list as `material.surface`.

### Task 5: MJCF compiler

**Files:**
- Modify: `services/engine/pyproject.toml`, `uv.lock` (`uv add mujoco`)
- Create: `icarus/design/__init__.py`, `design/compiler.py`, `design/surfaces.py` (surface → friction presets, shared with `material`)
- Test: `tests/design/test_compiler.py`

**Interfaces:**
- Consumes: Task 4 `Project` documents (assumed structurally valid).
- Produces: `compile_project(project: Project) -> CompiledModel` where `CompiledModel` is a frozen dataclass `{mjcf: str, model: mujoco.MjModel, objects: dict[str, str]}` (object id → MJCF body name); raises `CompileError(reason: str)` with MuJoCo's message made readable.

Mapping: each object is a `<body>` nested by `parent`; `transform` → `pos` and `quat` (deg XYZ → wxyz); `mesh` → `<geom>` type and size (scaled by `transform.scale`); `material` → `rgba` and friction; `physics_body` dynamic on a root object → `<freejoint/>`, `mass` on the geom (MuJoCo derives inertia from geometry: `<compiler inertiafromgeom="true"/>`), static → no joint, `contype`/`conaffinity` set; `collider` → friction and `solref` from restitution; `joint` → `<joint>` of its kind with `range` (deg → rad for hinge), `axis`, `damping`, and `fixed` = no joint; `motor` → `<motor>` (torque) or `<position>` with `ctrlrange` and `gear`; `distance_ray` → site + `<rangefinder>` per ray fanned over ±30°; `balance` → site + `<accelerometer>` + `<gyro>`; `touch` → site + `<touch>`; `light` → `<light>`; `spawn_point`, `goal_zone`, `zone` → non-colliding sites; `surface` → the ground plane's friction. Timestep 0.002, `integrator="implicitfast"`.

- [ ] **Step 1: Failing tests:** the empty project compiles to a model with zero bodies besides world; a dynamic box of mass 2 compiles with `model.body_mass` ≈ 2 and positive inertia; a hinge with limits ±45° gives `jnt_range` ≈ ±0.785; a motor on that joint yields one actuator with its `ctrlrange`; a zero-size geom raises `CompileError` whose reason mentions the object name, not an XML line.
- [ ] **Step 2: Run** `uv run pytest tests/design -q` → FAIL. **Step 3: Implement.** **Step 4: Run** → PASS.
- [ ] **Step 5: Commit** `feat(design): compile projects to MuJoCo models`.

### Task 7: Project store, revisions, undo and redo

**Files:**
- Create: `projects/store.py` (`ProjectStore`), `projects/files.py` (`write_atomic`, `append_line`)
- Test: `tests/projects/test_store.py`

**Interfaces:**
- Consumes: Tasks 3, 4, 6.
- Produces: `ProjectStore(root: Path)` with `list() -> list[ProjectSummary]`, `create(name: str, template: str) -> ProjectState`, `state(project_id) -> ProjectState`, `apply(project_id, batch: OperationBatch) -> ProjectState` (raises `RejectedBatch(issues, report)`), `revisions(project_id) -> list[Revision]`, `undo(project_id) -> ProjectState`, `redo(project_id) -> ProjectState` (both raise `NothingToUndo`/`NothingToRedo`), `delete(project_id)`. Old revisions are never deleted.
